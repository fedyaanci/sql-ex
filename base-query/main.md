# Конспект: базовые запросы SQL

Источник: `main.sql` (задачи 3–15 из sql-ex, блок base-query) + `memory.md`.
СУБД: PostgreSQL. Таблицы курса: `products`, `orders`, `couriers`, `courier_actions`.

---

## 1. Порядок выполнения ≠ порядок написания

**Пишем:** `SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT`
**Выполняется:** `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`

Следствия, которые уже пригодились:

- Псевдоним из `SELECT` работает в `ORDER BY` (и в `GROUP BY`), но **не** в `WHERE` — `WHERE` выполняется раньше `SELECT`.
- `ORDER BY` — единственное место, где можно ссылаться и на псевдоним, и на номер колонки (`ORDER BY 1`).
- `LIMIT` без `ORDER BY` = «какие-то n строк», порядок не определён.

## 2. Скелет запроса

```sql
SELECT col, expression AS alias
FROM   table
ORDER BY alias DESC, col ASC
LIMIT  5;
```

## 4. Шпаргалка по использованным функциям

| Функция | Что делает | Пример → результат |
|---|---|---|
| `LENGTH(s)` | длина строки в символах | `LENGTH('икра')` → `4` |
| `UPPER(s)` | верхний регистр | `UPPER('икра')` → `ИКРА` |
| `SPLIT_PART(s, delim, n)` | n-я часть строки | `SPLIT_PART('Молоко 1л', ' ', 1)` → `Молоко` |
| `CONCAT(a, b, ...)` | склейка; **NULL → пустая строка** | `CONCAT('№ ', NULL)` → `'№ '` |
| `\|\|` | склейка; **NULL → весь результат NULL** | `'№ ' \|\| NULL` → `NULL` |
| `COALESCE(a, b, ...)` | первый не-NULL | `COALESCE(NULL, 0)` → `0` |
| `DATE_PART('year', d)` | часть даты (число) | `DATE_PART('year', DATE '1990-05-06')` → `1990` |
| `x::type` | приведение типа | `price::varchar`, `now()::date` |
| `ROUND(x, n)` | округление до n знаков (тип не меняется) | `ROUND(105.1155, 1)` → `105.1` |
| `CASE` | условие внутри выражения | см. п. 5.6 |

## 5. Уточнения (важно)

### 5.1. NULL и приведение типа — записано верно
`DATE_PART('year', NULL)` → `NULL`, `NULL::varchar` → `NULL` (а не текст `'NULL'`).
Почти все функции в PostgreSQL объявлены как `STRICT`: если аргумент `NULL`, результат сразу `NULL`, тело функции не выполняется. Поэтому `COALESCE` — штатный способ подставить заглушку.

### 5.2. `=` и индексы — формулировка была неточной
- ❌ «с индексами `=` неприемлемо, надо `>=`» — **неверно**. `WHERE birth_date = DATE '1990-01-01'` прекрасно использует индекс.
- ✅ Проблема в **функции от индексируемой колонки**: `WHERE creation_time::date = DATE '2022-09-01'` → индекс по `creation_time` не используется.
- ✅ Как правильно — диапазоном:

```sql
WHERE creation_time >= DATE '2022-09-01'
  AND creation_time <  DATE '2022-09-01' + INTERVAL '1 day'
```

Правило: `::date` и другие функции — для вывода и группировки; фильтруй «сырую» колонку.

### 5.3. `::varchar` для даты зависит от настройки `DateStyle`
`creation_time::date::varchar` выдаёт `2022-09-01` только при `DateStyle = ISO` (это дефолт). В другом стиле получится `09/01/2022`. Для отчётов надёжнее явный формат:

```sql
to_char(creation_time, 'YYYY-MM-DD')
```

### 5.4. Сортировка, когда в колонке оказался текст (задача 11)
`COALESCE(DATE_PART(...)::varchar, 'unknown')` делает колонку **текстовой**, значит и сортировка строковая:

- `'unknown'` при `DESC` встаёт **сверху**, потому что в обычных локалях цифры идут раньше букв (`'unknown' > '2007'`).
- В PostgreSQL при `DESC` значения NULL по умолчанию идут первыми (`NULLS FIRST`), при `ASC` — последними (`NULLS LAST`), то есть NULL для сортировки «больше всех». Управлять явно: `ORDER BY x DESC NULLS LAST`.
- Для четырёхзначных годов текстовая сортировка случайно совпадает с числовой, но `'999' > '1000'` — уже нет. Это хрупко.
- Правило: `COALESCE` — для **вывода**; сортировку вешай на число или дату:

```sql
ORDER BY birth_date DESC NULLS LAST, courier_id
```

### 5.5. `LIMIT` без `ORDER BY`
В задаче 9 «первые 200 записей» — порядок не гарантирован. Нужен стабильный результат → всегда добавляй `ORDER BY`.
В задаче 6 при одинаковой длине названий у двух товаров `LIMIT 1` вернёт произвольный из них.

### 5.6. `CASE`

```sql
CASE status                       -- простая форма: только проверка на равенство
    WHEN 'completed' THEN 'Завершён'
    ELSE 'Другое'                 -- без ELSE результат NULL
END

CASE                              -- поисковая форма: любые условия
    WHEN price <= 100 OR name = 'икра' THEN price
    ELSE price * 1.05
END
```

- Условия проверяются сверху вниз, побеждает **первое истинное** → узкие условия ставь выше.
- `WHEN NULL` не сработает никогда (NULL не равен NULL) → `WHEN col IS NULL`.
- Типы всех ветвей приводятся к одному: `THEN 1 ELSE 'нет'` → ошибка.

### 5.7. Мелочи
- `ORDER BY new_price DESC` в задачах 12–13 работает: PostgreSQL разрешает псевдоним из `SELECT` в `ORDER BY`.
- `ORDER BY new_price` — сортировка по **вычисленному** значению, поэтому округление в задаче 13 влияет на порядок строк.
- `name = 'икра'` — сравнение регистрозависимое (`'Икра'` не сработает).

## 6. Следующие темы

- `WHERE` + `IS NULL` — фильтрация.
- Агрегаты, `GROUP BY`, `HAVING`.
- Условная агрегация: `COUNT(CASE WHEN status = 'completed' THEN 1 END)` считает только не-NULL; вариант `... ELSE 0 END` с `COUNT` — ошибка, посчитает все строки. В PostgreSQL то же самое короче: `COUNT(*) FILTER (WHERE status = 'completed')`.
- `JOIN`.
